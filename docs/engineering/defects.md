# Known defects and limitations

What is wrong or unverified in what exists **now**. Planned-but-missing features live in
[todo.md](todo.md). Conventions: [README](README.md).

## Open

|---|---|---|---|

| DEF-65 | firmware | Nodes hold 8 links (6 central, 6 peripheral), not the 14 of the link budget (architecture §5): each link task takes 5 KiB of RAM and the firmware is 23 KiB from the top of RAM at 8 ([spike](spikes/2026-11-04-firmware-ram-budget.md)). | DEF-66 | mesh | A replica remembers 64 summaries per peer for delta sync (`SUMMARY_MEMORY`), while a degree-6 node's 2-hop neighbourhood lists about 94 classes, so such nodes fall back to full exchanges. | DEF-67 | firmware | A sink keeps every record of its mesh, in a 24 KiB arena on the DK: about 500 records, a mesh of some 60 nodes (9 records a node in the simulator). | DEF-68 | firmware | Boot uses 29 KiB of stack before the mesh starts, for reasons not yet itemised (the HAL's init, MPSL, the SDC's initialisation, the replica), and the stack limit register now makes an overflow a hard fault with a record rather than silent corruption of the radio stack's statics below it, which is how the first mesh build died (spike 2026-11-04-firmware-ram-budget). The boot line prints the headroom and the high-water mark, and `firmware::run` logs the mark every 5 min. | A TAG has about 33 KiB of headroom with its tables halved; the 29 KiB of boot stack has to come down or be explained before the tables grow back. |
| DEF-63 | firmware | A transfer that broke off is remembered in RAM: the node restarting, or a sink taking a new upload from the host, starts the next one from byte 0. The slot's pages aren't checked for a resume either, as nothing but the whole image verifies. | A dropout followed by a restart costs a full transfer; over the air that's 70 s on a CS link, 5.5 min on a sink link. |
| DEF-64 | protocol | Nothing on the air names the protocol version: a build that changes a frame, record or session format can't talk to the previous one, so a rollout of it spreads one hop from a sink (which carries the image without running it) and no further, and the mesh view loses the nodes already on it until the rest follow. Builds that keep the formats roll out across hops by each updated node offering on its links. Since 2026-11-04 a peripheral serves a peer's channels and offers its update from encryption on, and keeps a peer that opens channels but sends no hello for 15 min: a node on an older build that connects to a sink and opens its telemetry channel, as the pre-mesh builds do, still takes the update the sink carries. | Keep formats compatible within a rollout, or roll a format change out from the sink outward; a protocol version in the beacon and the hello, with N and N−1 decoded, is the fix. |
| DEF-62 | firmware | Sync sessions on devices (stage 4) are built and untested with hardware, like the links (DEF-57). One session runs at a time on a node and a responder waits up to 20 s for the slot while its peer waits up to 30 s for a frame, so a busy node can fail a peer's session; three failures in a row drop the link. The session's first hello doubles as the link's role exchange, so a session that fails at link-up drops the link. A sink mirrors every record it keeps to the host as it arrives and all of them every 5 min; the host monitor shows them as lines, not yet as a mesh-state view (FR-S5). | Measure session length and failures on the desk mesh; a slow link with peripheral latency may need longer waits. |
| DEF-43 | firmware | The sink's UART receive logs about 36 framing errors per 490 KB upload. The CRC drops the damaged frames and the host resends each after 1 s, so an upload takes 63–77 s against about 50 s clean. Keeping the crystal on didn't help; the likely cause is `read_until_idle` stopping the receiver at gaps in a frame. | Uploads to the sink take about 20 s longer than they need. |
| DEF-25 | ranging | On the TAG pair at one desk placement, antenna path 3 of the 2×2 configuration reads 5–7 m with a phase residual of about 1.3 rad, against 3.3–3.8 m and 0.3–0.4 rad on paths 0–2 ([spike](spikes/2026-11-02-cs-antenna-diversity.md)). | DEF-12 | firmware | Building without a board feature prints the intended `compile_error!` plus a follow-on "unresolved import `consts`". | Cosmetic. |

## Fixed

| ID | Defect | Fix |
|---|---|---|
| DEF-29 | A stored record took 136 B of RAM, about three times its wire size, as the node record's eight 64-bit neighbour IDs sized the record enum. | Devices keep records and outbox entries postcard-encoded in byte arenas (`navgrid_mesh::Arena`, 2026-11-04), about 50 B a record; the host keeps structs. The summaries are packed to 11 B as well. |
| DEF-39 | An update offer was made once per connection, and a transfer cut short started again from byte 0 at the next. | Resume and re-offer (2026-11-04): the receiver remembers a transfer that broke off and asks for the same build from its last whole page (`Want { from }`, which the sender already honoured), and every node offers what it carries on each link every 3 min as well as at link-up, so a peer that declined while unconfirmed, or was busy on another link, gets it next time without a reconnect. In RAM only (DEF-63). |
| DEF-31 | Routes came only from records pushed toward sinks, so a command could reach only a node whose records had reached a sink. | A record for a node with no route goes toward the peer behind which the node records held here place it, searching their neighbour lists four hops deep (2026-11-04). Node records travel up as well, so the window is a new node's first minutes. |
| DEF-30 | When a node lost its path to every sink, hop counts counted up through its peers to `MAX_HOPS` before reading unreachable; 226 pushes refused in a one-hour partition of 20 nodes. | Split horizon with poisoned reverse (2026-11-04): a node's hello to the peer its only sink path runs through says unreachable, so the two can't count up through each other. The same partition refuses no push. |
| DEF-28 | Summaries were about 80 % of a session's bytes, 650 B a side, sent whole every time. | Delta sync (2026-11-04): each side remembers the summaries of its last complete session with a peer and sends only the classes that changed (a class dropped goes as a zero hash); either side without memory gets a full exchange, and a session that breaks off forgets. The simulator's sessions fell to 115 B a side at p50 (20 nodes) and 125 B (500 nodes, 4 sinks), summaries 30 % of that. |
| DEF-27 | Desired state was not authenticated: any node could write a `Desired` record under the controller's ID. | A MAC under the controller key, AES-CMAC of the fleet key, over origin, version, target and command (`navgrid_mesh::auth`, 2026-11-04); nodes act only on records that verify. The controller's node ID is still a constant until provisioning carries it. |
| DEF-1 | Telemetry went to one sink over a dedicated link, with no forwarding over ranging contacts; the sink served 4 nodes. | Stage 3 and 4 (2026-11-04): telemetry rides any mesh link whose peer is a sink, and mesh records travel by sync sessions over every link, hop by hop toward sinks, which mirror them to the host. |
| DEF-44 | The registry recorded only what `navgrid flash` and `navgrid update --probe` wrote, so it missed updates over the air and showed "firmware unknown" for a device flashed before enrolment. | The monitor records the build each device reports in its Hello, Health and Boot, dated, and re-reads the registry when an unknown device reports. |
| DEF-50 | A reflector provisioned with a sink couldn't connect its sink link: the SDC refused `LE Extended Create Connection` (Command Disallowed) after legacy advertising. Then, with beacons on extended PDUs, an initiator's CS link landed anywhere relative to its sink link, and on 5 fresh boots of 5 N001 lost every 4th procedure (8.0/s): connections made from extended advertising don't get the SDC's ACL event spacing (DEF-26). At 120 ms the reflector's own link also sat on 2 procedures in 4. | Beacons advertise through the extended commands with legacy PDUs, so centrals space their links again, and a reflector's sink link runs at 1 s, drifting across the CS procedures. Three fresh boots of N001: 11.0/s with N002 reporting, 14–22 empty procedures a minute, its 1 s link's cost. |
| DEF-47 | The initiator held the central role while it waited, unbounded, to connect to its CS peer. With the peer away its sink link couldn't connect, so it reported nothing; the sink, updated meanwhile, had no node link for 5 min and reverted. | The peer connect gives up after 10 s and yields, so the uplink connects between tries. With N002 away for 2.5 min, N001 kept reporting Health. |
| DEF-42 | On the initiator's sink link, 2M and 251-byte packets let only one exchange into each 2.5 ms event, so the uplink carried at most 8.3 frames/s and the outbox overflowed, even with no update running. | Full-length packets only during an update (`update::listen`), and credits returned four chunks at a time. At rest the uplink is back to 11.1/s with an empty outbox; during an update it carries 6.6/s instead of none (DEF-45). |
| DEF-41 | A sink's update offer to a node over the sink link failed: the transfer stalled near its end, or the node never answered the channel request. The node's telemetry sender, with an outbox kept full by DEF-42, took TrouBLE's per-link send lock again each time it released it, so the update channel's accept and returned credits never went out. | The telemetry sender yields after each frame. The sink then passed a 507 KB update to N001 in 273 s, N001 installed it and passed it to N002 ([spike](spikes/2026-11-03-updates-through-the-sink.md)). |
| DEF-26 | The initiator's sink link collided with its CS subevents. At first, at 100 ms about a third of procedures came back empty, and at 500 ms the link dropped after its supervision timeout. With the CS link up before the sink link, every fourth procedure stayed empty (8.3/s) even with spacing. | ACL event length 2.5 ms, a 120 ms sink interval (a multiple of the CS link's 30 ms), and the central ACL spacing set before each connection. The sink link has to come first, with the CS link 2.5 ms after it, so when the sink link connects under a CS link, the CS link reconnects after it. 11.1/s with no empty procedures in four runs, three of them re-placed (2026-11-03). |
| DEF-5 | `NodeConfig` was a compiled-in default, with no flash storage or provisioning. | A CRC-checked provisioning page in the second-to-last RRAM page, written by `navgrid provision` through the probe, survives firmware flashing. |
| DEF-14 | Role, peer and sink were build-time variables, and links paired Just Works on every connect. | Role, bring-up peer and sink come from provisioning, and links between provisioned devices encrypt under keys derived from the fleet key (D-7), without pairing. |
